# 「行测刷题」Android 应用开发方案

> 基于 Tauri 2.x · **桌面端先行开发，真机后置验证** · 最终交付 Android 端 · 离线优先  
> 工作区：`D:\project\what-exam` · 更新：2026-10-09

---

## 1. 项目概述

### 1.1 目标

基于现有 4 份行测题库 PDF（中公教育内部资料），构建一个**纯离线、轻量、单手可刷**的 Android 刷题 App，支持做题、对答案看解析、错题本、数据统计，帮助备考公务员行测。

### 1.2 开发策略：桌面端先行，真机后置

**开发期跑在 Windows 桌面窗口（`pnpm tauri dev`），功能与 UI 全部完成后再接 Android 工具链做真机适配与打包。**

|      | 桌面开发阶段（M0–M3）                                              | 真机验证阶段（M4）                       |
| ---- | ---------------------------------------------------------- | -------------------------------- |
| 运行宿主 | Windows 桌面窗口（WebView2）                                     | Android 真机（System WebView）       |
| 命令   | `pnpm tauri dev`                                           | `pnpm tauri android dev/build`   |
| 需要装的 | **已具备 Rust / WebView2 / Node / VS2022**，仅补 pnpm（见 6.1 实测表） | Android SDK/NDK + JDK17 + 真机或模拟器 |
| 迭代速度 | 秒级热重载，DevTools 直连                                          | 需 adb 连接，`chrome://inspect` 调试   |
| 产出   | 可用桌面程序（副产品）                                                | 签名 APK                           |

**为什么这么做：**

1. 安卓工具链（NDK 版本、Gradle、签名）是最容易卡住的一环，放在最后一次性解决，不阻塞功能开发。
2. 桌面 `tauri dev` 热重载秒级、Chrome DevTools 直接可用，开发效率显著高于真机。
3. 前端代码 100% 复用，真机阶段只做**适配与验证**，不做功能重写。

**代价与控制措施（防止真机阶段返工）：** 见 **2.4 桌面优先开发的约束**。

### 1.3 现有资料盘点（已实际解析验证）

| 题本      | 题量        | 页数    | 内容构成                                          | 特殊点                         |
| ------- | --------- | ----- | --------------------------------------------- | --------------------------- |
| 数量关系    | 120 题     | 15 页  | 数字推理 + 数学运算                                   | 大量带分数（如 2½），文本提取后碎裂为多行      |
| 判断推理    | 130 题     | 35 页  | 逻辑判断(1-80) / **图形推理(81-110)** / 类比推理(111-130) | 图形推理题干为矢量图形，**必须图片化**       |
| 言语理解与表达 | 130 题     | 38 页  | 逻辑填空 + 片段阅读                                   | 纯文本，解析质量最好                  |
| 资料分析    | 120 题     | 38 页  | 20 组材料，每组 5-6 题                               | 材料含表格/图表，**表格无法纯文本还原，需图片化** |
| **合计**  | **500 题** | 126 页 | 四大模块                                          | 答案 PDF 含逐题文字解析              |

关键结论：

1. **500 题 + 全部文字解析**，总文本量约 14 万字，完全可内置进 App。
2. **两类内容必须以图片呈现**：判断推理的图形推理题（约 30 题）、资料分析的材料表格（约 20 组）。
3. PDF 为文本型 PDF（非扫描件），文字可直接提取，解析工作以「自动提取 + 人工校对」为主。

## 2. 总体方案

### 2.1 技术选型

| 层        | 选型                                      | 理由                                               |
| -------- | --------------------------------------- | ------------------------------------------------ |
| 应用框架     | **Tauri 2.x**（用户指定）                     | 一套前端同时跑桌面与安卓；APK 体积小（壳约 3-5MB）；Rust 侧性能好         |
| **开发宿主** | **Windows 桌面窗口**（阶段一）→ Android 真机（阶段二）  | 桌面热重载快、DevTools 好用，先把功能做完再上真机                    |
| 前端框架     | Vue 3 + TypeScript + Vite               | 生态成熟、上手快、移动端性能足够                                 |
| UI 组件库   | Vant 4（移动端组件库）                          | 专为移动 Web 设计，中文文档，自带 ActionSheet/Progress/Toast 等 |
| 状态管理     | Pinia                                   | Vue 3 官方推荐                                       |
| 本地存储     | **SQLite**（`tauri-plugin-sql`）+ JSON 资产 | 题库为只读 JSON 随包内置；做题记录/错题/统计用 SQLite               |
| 图表       | ECharts（按需引入）或轻量 SVG 自绘                 | 正确率趋势、模块分布                                       |
| 数学公式     | 自定义渲染（分数用上下结构 CSS）                      | 数量关系只需分数/上标，不必引 KaTeX（体积大）                       |
| 数据管线     | Python（PyMuPDF）                         | 解析 PDF → JSON + 裁剪图片，一次性脚本                       |

### 2.2 架构

```
  阶段一(开发)                              阶段二(交付)
┌──────────────────────────┐   ┌─────────────── Android APK ───────────────┐
│ Windows 桌面窗口 390×844 │   │  WebView (Android System WebView)         │
│ (WebView2，模拟手机视口) │   │                                            │
└────────────┬─────────────┘   └──────────────────────┬───────────────────┘
             └────────── 同一套 Vue 前端代码 ──────────┘
                                │
┌───────────────────────────────┴────────────────────────────────────┐
│  Vue 3 + Vant 前端                                                  │
│   页面层：首页/刷题/答案解析/错题/统计                                │
│   状态层：Pinia (session, settings)                                 │
└───────────────────────┬────────────────────────────────────────────┘
                        │ Tauri IPC (invoke)
┌───────────────────────┴────────────────────────────────────────────┐
│  Rust Core (tauri v2)  plugins: sql / store / fs                    │
└───────────────────────┬────────────────────────────────────────────┘
                        │
   SQLite: records.db（做题记录/错题/统计）
   Assets: questions.json（500题内置题库）
   Assets: /img/graph/*.png（图形推理）  /img/material/*.png（资料图表）
```

**设计原则：**

- 题库是**只读资产**，随包内置（`src-assets`），不放 SQLite —— 500 题 JSON 约 1-2MB，一次载入内存分页渲染即可，避免首次启动迁移。
- 用户数据（做题记录、错题、收藏、统计）全部进 SQLite，天然支持后续导出/同步。
- Rust 层**尽量零自定义代码**，只靠官方插件 —— 这是"一套代码跑桌面 + 安卓"能成立的前提。

### 2.3 为什么这套方案成立（选型权衡）

- vs **原生 Android (Kotlin)**：开发效率高一倍以上，但性能/体验上限略低。本项目 UI 极简单（列表 + 表单 + 图表），WebView 方案绰绰有余。
- vs **Flutter/RN**：若不要求 Tauri，Flutter 也是好选择；但 Tauri 2 已 GA 移动端，Web 栈复用度高，且本项目无重动画需求。
- **Tauri Android 的已知短板**（要有预期）：WebView 依赖系统版本（minSdk 24 以上普遍 Chromium 100+，风险可控）；调试需 `chrome://inspect`；`tauri android dev` 迭代比桌面慢 —— 这正是选择桌面先行开发的原因。

### 2.4 桌面优先开发的约束（防返工）

桌面开发最大的风险是"写着写着变成桌面软件，上真机要重做布局"。以下为**硬性约束**：

**A. 视口模拟（最关键）**

- `tauri.conf.json` 里把开发窗口固定为手机尺寸：
  ```jsonc
  "windows": [{
    "label": "main",
    "width": 390, "height": 844,      // iPhone 14 逻辑分辨率，即手机竖屏
    "resizable": false,
    "titleBarStyle": "Transparent",   // 尽量贴近手机无标题栏观感
    "title": "行测刷题"
  }]
  ```
- CSS 里不使用任何 `@media (min-width: ...)` 桌面断点；容器宽度 `100%`，不写死 `px` 宽度。
- 布局单位用 `rem`（Vant 默认 375 设计稿）或百分比，**禁止把 hover 态作为唯一交互入口**。

**B. 只用跨平台能力**

- 只用 `@tauri-apps/plugin-sql / plugin-store / plugin-fs / plugin-dialog`，**不使用**菜单、托盘、多窗口、窗口尺寸调整、`plugin-opener` 等桌面倾向 API。
- 路径一律走 `appDataDir()`，不硬编码 Windows 路径。
- 键盘/鼠标不作为必需交互：所有操作必须能靠点击完成（别依赖右键、双击、hover 菜单）。

**C. 从第一天就预留移动端差异**

- 顶部/底部预留安全区变量 `env(safe-area-inset-*)`，桌面下为 0，真机自动生效。
- 输入框（搜索）按软键盘弹出设计，避免被遮挡。
- 返回逻辑统一走路由，不依赖硬件返回键（真机阶段再补返回键拦截）。
- 只用系统字体族，不指定 Windows 专有字体（微软雅黑在安卓会回退，需确认回退效果可接受）。

**D. 真机阶段验证清单（M4 逐项过）**

| # | 验证项              | 常见问题                |
| - | ---------------- | ------------------- |
| 1 | 布局在真机竖屏无横向滚动、无溢出 | 桌面视口宽度对但真机 DPR/字体不同 |
| 2 | 图片题全屏缩放、双指手势     | WebView 手势与页面滚动冲突   |
| 3 | 分数/特殊符号渲染        | 字体回退                |
| 4 | SQLite 首次建库与读写   | 安卓沙箱路径              |
| 5 | 深色模式、字体大小设置生效    | —                   |
| 6 | 硬件返回键行为、误触退出     | 需监听返回键做二次确认         |
| 7 | 冷启动耗时、切题流畅度      | 低端机性能               |
| 8 | 数据导出/导入（文件读写权限）  | 安卓权限与 SAF           |
| 9 | 横屏/分屏（建议锁竖屏规避）   | —                   |

## 3. 数据方案（本项目成败关键）

### 3.1 题库 Schema（questions.json）

```jsonc
{
  "version": 1,
  "modules": ["数量关系", "判断推理", "言语理解与表达", "资料分析"],
  "questions": [
    {
      "id": "panduan-081",                // 模块前缀 + 原题号
      "module": "判断推理",
      "subType": "图形推理",               // 二级题型
      "stem": "从所给选项中，选择最合适的一个…",
      "stemImage": "img/graph/panduan-081.png",  // 可选：题干图
      "options": ["A", "B", "C", "D"],    // 图形题 options 为空
      "optionsImage": "img/graph/panduan-081-opt.png", // 可选：选项图
      "answer": "B",
      "explanation": "解析全文…",
      "materialId": null,                 // 资料分析题指向所属材料
      "source": "中公行测题库"
    }
  ],
  "materials": [
    {
      "id": "ziliao-m1",
      "text": "2022年2月，“东数西算”工程正式全面启动…",
      "image": "img/material/ziliao-m1.png"  // 表格截图
    }
  ]
}
```

### 3.2 PDF → 题库解析管线（Python 脚本）

```
PDF ──PyMuPDF──▶ 文本流 ──正则切题──▶ 题目/选项/解析/答案
 │                                        │
 └─页面渲染(150dpi)──按题号定位─▶ 裁剪图片 ─┤
                                          ▼
                              questions.json + /img/*.png
                                          ▼
                              人工抽查校对（每模块抽 20 题）
```

要点：

1. **切题规则**：`(?m)^\s*(\d{1,3})[\.、]` 已验证能完整切出 500 题（题目 PDF 命中率 100%）。
2. **答案对齐**：答案 PDF 同样按 `N.【答案】X。解析：…` 切分，与题目按模块+题号 join，已有数据验证可行。
3. **图片化策略**：
   - 图形推理（判断推理 81-110 题）：按题号 y 坐标裁剪整题区域为 1 张图。
   - 资料分析材料表格：每组材料裁剪表格部分（题干文字保留文本，表格转图），或整段材料截图。
   - 裁剪坐标通过 `page.search_for("81.")` 拿到题号锚点位置计算。
4. **数量关系带分数**：如 `2.1`（2 又 1/2）在提取时碎成多行，需用 PyMuPDF 的 block 坐标重组，存为结构化标记，前端 CSS 渲染上下分数。
5. **校对工具**：写一个本地 HTML 校对页，左右对照「原 PDF 页截图 vs 解析出的 JSON」，人工过一遍效率最高（约 3-5 小时）。

### 3.3 用户数据 Schema（SQLite records.db）

```sql
-- 做题记录
CREATE TABLE attempts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id TEXT NOT NULL,
  chosen TEXT,               -- 用户选择 A/B/C/D
  is_correct INTEGER NOT NULL,
  duration_ms INTEGER,       -- 本题用时
  mode TEXT,                 -- practice / exam / wrong-redo
  created_at TEXT DEFAULT (datetime('now','localtime'))
);
-- 错题本
CREATE TABLE wrong_book (
  question_id TEXT PRIMARY KEY,
  wrong_count INTEGER DEFAULT 1,
  mastered INTEGER DEFAULT 0,     -- 移出错题本
  last_wrong_at TEXT,
  next_review_at TEXT             -- 间隔重复(SM-2)下次复习时间
);
-- 收藏
CREATE TABLE favorites (question_id TEXT PRIMARY KEY, created_at TEXT);
-- 每日统计
CREATE TABLE daily_stats (
  date TEXT PRIMARY KEY,
  attempted INTEGER, correct INTEGER, duration_ms INTEGER
);
-- 设置
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT);
```

### 6.2 阶段一：桌面开发（立即可开始）


### 6.3 阶段二：Android 真机（M4 再装，不阻塞前期）

1. **Android Studio**：Android SDK Platform 34、SDK Build-Tools、**NDK (r25+)**、CMake。
2. **JDK 17**（关键）：AGP/Gradle 官方推荐 JDK 17。本机当前是 JDK 25，版本过新易与 Gradle 插件不兼容。
   - 方案 A（推荐）：装 Android Studio 自带的 **jbr（JDK 17/21）**，构建安卓时把 `JAVA_HOME` 指向它：
     ```bash
     JAVA_HOME="C:/Program Files/Android/Android Studio/jbr"
     ```
   - 方案 B：先直接用 JDK 25 试 `tauri android build`，报错再降级。
3. Rust 安卓目标：
   ```bash
   rustup target add aarch64-linux-android armv7-linux-androideabi
   ```
4. 环境变量：
   ```bash
   JAVA_HOME="C:/Program Files/Android/Android Studio/jbr"
   ANDROID_HOME="$LOCALAPPDATA/Android/Sdk"
   NDK_HOME="$ANDROID_HOME/ndk/26.x.x"
   ```
5. 命令：
   ```bash
   pnpm tauri android init          # 生成 gen/android（只需一次）
   pnpm tauri android dev           # 真机/模拟器调试
   pnpm tauri android build --apk   # 产出 APK
   ```

### 6.4 已踩坑记录（M0 实战，后续复用）

1. **包管理器**：本机没有 pnpm，且不便全局安装 —— 全程用 **npm** 即可（`npm create tauri-app` 支持 `--manager npm`），命令把文档里的 `pnpm` 换成 `npm`。
2. **schemars 0.8.22 × indexmap 1.9.3 编译失败**（`E0107: struct takes 3 generic arguments`）：schemars 以 `default-features = false` 引入 indexmap 1.x，缺 `std` 导致泛型默认值丢失。修法是在 `src-tauri/Cargo.toml` 的 `[dependencies]` 与 `[build-dependencies]` 都加：
   ```toml
   indexmap = { version = "1.9", features = ["std"] }
   ```
3. **rustc 高并发崩溃**（`STATUS_STACK_BUFFER_OVERRUN` / exit code `0xc0000409`）：并行度打满时多个 rustc 进程崩溃。修法是限制并发：
   ```bash
   CARGO_BUILD_JOBS=2 npm run tauri dev
   # 或 cargo check -j 2
   ```
4. **Tauri dev 连不上 dev server**：Windows 上 Vite 默认只监听 IPv6 的 `::1`，而 Tauri 走 IPv4。修法是 `vite.config.ts` 里 `server.host` 固定 `127.0.0.1`，同时 `tauri.conf.json` 的 `devUrl` 改为 `http://127.0.0.1:1420`。
5. **脚本启动的 dev server 会随终端会话结束被回收**：调试时要把 Vite 和 Tauri 放在同一条命令里启动，否则 Tauri 会一直等 `Waiting for your frontend dev server`。

### 6.5 签名与发布

- 生成 keystore：`keytool -genkey -v -keystore release.keystore -alias whatexam -keyalg RSA -validity 10000`
- 在 `gen/android` 的 `build.gradle` 配置 signingConfig；自用直接装 APK。
- 注意：中公资料标注"内部资料 免费交流"，**建议仅自用，不公开分发**。

## 8. 风险与对策

| 风险                                   | 概率                 | 对策                                                                       |
| ------------------------------------ | ------------------ | ------------------------------------------------------------------------ |
| PDF 解析错漏（选项粘连、跨页题目）                  | 高                  | 切题后做完整性校验（题号连续、4 选项齐全、答案可 join），异常项进人工队列                                 |
| 资料分析表格裁剪坐标不准                         | 中                  | 用表格标题文字（"表1""表2"）作锚点 + 校对页人工微调                                           |
| 带分数/特殊符号渲染错乱                         | 中                  | 结构化存储 `{整数}{分子}{分母}`，CSS 渲染，不依赖字体                                        |
| **桌面开发跑偏成桌面软件，真机要重做布局**              | **中高（桌面先行的主要新风险）** | 严守 2.4 约束：固定 390×844 窗口、移动优先 CSS、禁用桌面独占 API、禁止 hover 作为唯一入口              |
| 桌面与安卓 WebView 行为差异（滚动、手势、字体回退、100vh） | 中                  | 避免 `100vh`（用 `100dvh`/flex）；M4 按 9 项清单逐项验                                |
| **JDK 25 与 Gradle/AGP 不兼容**          | 中                  | M4 优先用 Android Studio 自带 jbr（JDK 17/21）并切换 `JAVA_HOME`；先用 JDK 25 试，报错即降级 |
| Tauri Android 工具链踩坑（NDK/Gradle 版本）   | 中                  | 后置到 M4 集中排障，不阻塞功能开发；M4 预留整天时间                                            |
| 安卓文件读写权限（数据导出/导入）                    | 中                  | 优先写 appDataDir；导出时再走用户授权保存，必要时引入 `plugin-dialog`                         |
| WebView 低版本兼容                        | 低                  | minSdk 24，主流设备均 Chromium 100+；避免使用过新 CSS 特性                              |
| 版权                                   | —                  | 中公资料标注"内部资料 免费交流"，**仅自用不分发**；如上架需替换自研题库                                  |
